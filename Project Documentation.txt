Inventory-Driven Channel Manager System
1️⃣ PROJECT OVERVIEW (WHAT IS THIS SYSTEM?)

This project is a frontend-first Channel Manager MVP designed for hotels / properties to:

Control room availability

Manage pricing dynamically

Apply stop-sell rules

Visualize inventory performance

Generate business reports

Prepare a clean foundation for OTA integrations and backend APIs

⚠️ This is NOT a PMS.
It is intentionally designed as a Channel Manager, which focuses on supply control, not guest operations.

2️⃣ CORE DESIGN PHILOSOPHY
🔑 Inventory Calendar = Single Source of Truth

Every feature in the system derives from inventory calendar data.

There is:

❌ No dependency on reservations

❌ No booking-first logic

❌ No hardcoded metrics

Everything is calculated from:

Room → Calendar → Status + Price

This mirrors how real-world channel managers operate.

4️⃣ WHAT WAS INTENTIONALLY REMOVED (AND WHY)
❌ Reservation / PMS Module

Reservation logic was intentionally removed because:

Channel managers do not own bookings

OTAs send bookings via APIs

PMS handles guest lifecycle

Keeping reservations would:

Add unnecessary coupling

Complicate OTA sync

Reduce scalability

Instead:

Calendar stop-sell represents sold inventory

OTA bookings will later mark dates as stop-sell

This is a correct industry decision, not a shortcut.

5️⃣ EVENT-DRIVEN ARCHITECTURE (IMPORTANT)

The entire frontend follows an event model:

Inventory Change
      ↓
inventoryUpdated Event
      ↓
Dashboard + Reports Update
Why this matters:

Mirrors backend pub/sub systems

Easy to migrate to WebSockets / Kafka / Redis later

Keeps modules loosely coupled

7️⃣ HOW OTA INTEGRATION WILL WORK (FUTURE SCOPE)
🔼 OTA Push (Outbound)

Push availability (stop sell)

Push rates (base + override)

🔽 OTA Pull (Inbound)

Receive booking → mark date stop-sell

Receive cancellation → free date

Suggested Backend APIs
POST /api/inventory/availability
POST /api/inventory/rates
POST /api/ota/webhook/booking
POST /api/ota/webhook/cancel

Frontend code will not change significantly.
